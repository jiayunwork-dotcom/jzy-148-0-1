一个在小贷公司做风控的朋友来问我能不能帮个忙。他们的申请评分卡一直是外包团队用 SAS 做的，每半年重训一次，出一份 Excel 交付，中间的分箱怎么合并、系数怎么来的，内部没人说得清；监管来检查时要求能复现，他们就很被动。他想要一个内部服务：把开发样本丢进去，自动做出一张评分卡，每一步的中间结果都留下来可查，之后在线打分也走这张卡。

建卡作为后台作业运行。输入是一份 CSV 开发样本：一列 0/1 违约标签，其余是特征列，数值型和类别型都有，允许缺失。每个数值特征先等频切成不超过 20 个初始箱，再相邻合并，直到各箱 WOE 随特征值单调（方向由数据决定）、每箱样本占比不低于设定下限（默认 5%）、每箱好坏样本都不为零；类别特征按坏样本率排序后同样合并。缺失值始终单独成一箱。每个特征输出分箱边界、各箱好坏计数、WOE 与 IV。用户可以指定入模特征清单；未指定时按 IV 阈值自动筛选。然后用各特征 WOE 作为自变量拟合逻辑回归，拟合用你自己实现的牛顿迭代，收敛不了就让作业失败并记下原因。最后按基准分、基准 odds 和 PDO 把系数换算成每箱分值，截距分摊方式写进说明。

有这些性质需要验证：拟合收敛后，全样本平均预测违约概率等于样本违约率（带截距的逻辑回归必然如此），误差 1e-6 以内；把标签整体取反重新建卡，各箱 WOE 变号、IV 不变；把样本原样复制一份再建卡，分箱、WOE 和系数都不变；某申请人各箱分值之和就是总分；总分增加一个 PDO，对应 odds（好/坏）翻倍；PD 随总分严格单调下降且始终在 (0,1) 内；数值特征合并后的 WOE 序列确实单调。

建卡结果以版本保存：同一个卡名可以多次建，每次一个新版本，保留分箱、系数、分值表和训练指标（KS、AUC、各特征 IV）。打分接口指定卡名与版本（缺省取最新），接收原始特征值，自动落箱，返回总分、PD 和每个特征的落箱与得分；遇到训练时没见过的类别，按「未见类别」处理并在结果中标出，不静默归入某一箱。也可以上传一批申请人批量打分，单条出错只影响那一条。样本少于 500 行、标签不是 0/1 或全为同一类、PDO 不为正、入模特征不存在，都在作业开始前拒绝。几个建卡作业可以同时跑，各自的中间结果不会混到一起。

后端 Python 3.12 + FastAPI，可用 NumPy 做矩阵运算，但分箱合并、WOE/IV、逻辑回归、KS/AUC 都要自己实现，不用 scikit-learn、statsmodels 这类库。样本解析、分箱引擎、回归拟合、评分换算、模型评估、作业调度、版本存储、接口层分模块组织。数据存 PostgreSQL 16（postgres:16-alpine），后端镜像用 python:3.12-slim，拿 Docker Compose 编排这两个服务。pytest 覆盖上面列出的性质，并附一份小样本，可以手算前两个特征的 WOE 来核对。只提供 HTTP 接口，无前端。
